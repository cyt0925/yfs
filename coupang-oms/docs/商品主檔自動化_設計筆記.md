# 商品主檔自動化 設計筆記（為什麼長這樣）

> 這份是「腦袋裡的東西」：每個名詞的真正意思、每個決定背後的原因、做過又拆掉的東西。
> 程式怎麼跑看 `master/` 各檔的 docstring；這裡講的是**為什麼**。改需求前先讀這份，很多坑已經踩過。

## 一、這個模組在取代什麼

OP 原本的手工流程（每次酷澎改單就要重來一遍）：

1. 從凱特系統下載「訂單彙總表」（就是訂單管理系統吃的那份整合表）。
2. 貼進「專案報價檔」：一個交貨日一個分頁、PO 之間黃色空白列；永豐料號／品類／品牌／箱入數／單價 用 VLOOKUP 從「總表」撈。
3. 改完重做樞紐：國條 × 出貨數量(箱) → 每個交貨日的出貨總箱數。
4. VLOOKUP 回填「總表」對應日期欄（貼成值）。

系統的三步：① 商品主檔（總表／酷澎主檔鋪底）→ ② 訂單明細（匯彙總表、改數量交期）→ ③ 總表（自動算）。
匯出兩種檔：**專案報價檔**（給業務）、**總表**（給 Chloe／PG）。

## 二、名詞的真正意思（很多是問出來的，別再問同事一次）

| 名詞 | 意思 | 注意 |
|---|---|---|
| 線別 | 供應商／品牌群：寶僑、瑪氏、CPG-潔品、CPG-紙品… | 彙總表每一列自己帶；**總表沒有線別欄**；酷澎主檔一個線別一份、有線別欄 |
| 紙潔 | 畫面上把 CPG-潔品＋CPG-紙品 合併顯示的名字 | 規則寫死在 `common.LINE_GROUPS_DEFAULT`（CPG 開頭 → 紙潔、空白 → 未分類、其他照原名）。曾做成可設定面板，同事看不懂，拿掉 |
| 未分類 | 彙總表線別欄空白的單 | 一定要有地方放，畫面標紅 |
| 國條／條碼 | 商品鍵。**箱裝品是 14 碼、開頭 1**（單品條碼前加 1） | 主檔、總表 Barcode 欄、彙總表三邊都用同一個碼，對得上；不要自己去掉開頭的 1 |
| 箱入數 | 一箱幾個。箱裝品箱入數＝1（酷澎下單單位就是箱） | 以主檔為準，沒有才退回整合表自帶的（標「檔」），都沒有標紅「算不出來」，**絕不當 0** |
| 箱數 | 出貨數量 ÷ 箱入數，**不湊整**（62÷24＝2.5833） | 同事明確說「以出貨數量為主」，別加四捨五入邏輯 |
| 業務報價單價(含稅) | 酷澎主檔的欄位，**＝總表的 COGS**，同一個欄位 `cost_price` | 進報價檔 K 欄 |
| 報價備註 | 酷澎主檔的欄位，**＝總表的 Note**，同一個欄位 `note` | 進報價檔 O 欄；OP 自己的備註接在後面；凱特那串 MPO_ 不進去 |
| 請核對 | 主檔那筆是匯訂單時自動建的（`auto_created`），不是總表／主檔給的 | 不是說數字錯。重匯主檔會自動解除 |
| 總表裡還沒有的商品 | 訂單有下、總表查不到（以前 VLOOKUP 出 #N/A 的那些） | 照 Chloe：**不混進總表**，另外列出來 |
| 專案報價檔 | 檔名就叫 `專案報價檔.xlsx`；分頁 `0904交貨`、`0903交貨`… **新的在前**；可跨月（month_to） | A～R 欄的來源見 README |
| 總表 | Chloe 維護的 PG 總表，只吃「每個日期的出貨箱數」 | 匯出必須**跟她的檔一模一樣含順序**，所以是拿她的檔當底稿填，不是自己畫 |
| 匯入批次 | 每按一次「確認匯入」一批。訂單列記 `first_batch_id`（第一次出現）、`last_batch_id`（最後被改到）、`last_batch_changes`（改了什麼） | 用 id 不用時間戳：同一秒連按兩次時間戳會撞 |

## 三、關鍵決定與原因

- **主檔鍵＝國條，全公司一份；訂單鍵＝(PO, SKU)，線別只是列上的原始值。** 因為總表沒有線別、同一張 PO 會跨線別（CPG-潔品／CPG-紙品）。改交貨日整張 PO 一起搬，不分線別。
- **人改過的欄位（出貨數量、交貨日、備註）匯入不覆蓋**，各自旗標；每筆帶版本號，兩個人互改回 409。
- **酷澎拿掉的品項不刪列**：PO 在檔案裡、品項不見 → 列保留、出貨歸 0、標 `missing_in_file`，再出現自動恢復。整張 PO 不在檔案裡的一律不動。
- **總表只列有交貨的商品**（畫面），匯出走底稿：① 匯進主檔的檔如果有 `M/D交貨` 日期欄就是業務的總表，整份存成 `mst_templates`（線別看這批商品在主檔屬於誰，都不知道就當寶僑）。沒有另外的「上傳底稿」步驟——做過，同事說多一步沒意義。
- **總表缺的日期自動插欄**（Chloe 提的）：插在日期順序該在的位置，模仿 Excel 插欄改右邊所有公式、合併格、欄寬；別的工作表／外部檔的參照不動；該月 TTL 加總欄重寫成涵蓋整個區塊；`M/交貨` 空欄是業務的不動；整個月都沒有就補「日期欄＋TTL」。**固定 1～30 日**那個方案沒採用（表會太寬）。
- **各次匯入的變動**（2026-09-16 第三版）：上面只留**一行**「最近匯入 時間 新增／有變／消失 ＋ 只看這次變動 ＋ 匯入紀錄」。
  表格裡最近一次動到的列左邊一條色條＋小標籤（綠新增／黃有變／紅消失），不點任何東西就看得出差別；
  行事曆格子右上角同色角標「新3 變2 消1」，只看某次時沒動到的天壓淡。每一次匯入的數字收在「匯入紀錄」小視窗
  （會捲動，一次一列，點一列只看那次），匯 100 次首頁還是一行。選了某次**不動月份**，這個月沒變動就一句「變動在 9 月 → 切過去」。
  「消失」＝上次有、這次檔案裡沒了（missing_in_file），跟「有變」互斥。匯出多一欄「本次變動」。
- **第四版（2026-09-17，nicole 匯了 6 張跨月 PO 之後）**：主數字改 **PO 張數**（新增 6 張 PO · 48 品項），品項數當小字；
  行事曆角標也是 PO 張數。「只看這次變動」這個詞太不正式，Jerry 定案叫 **「依匯入批次篩選」**：一顆按鈕拉開右側抽屜
  （每批一列，最新在上），選了某批那一行寫「依匯入批次篩選：09-17 08:56 這批」＋「清除批次篩選」。
  選批次時**月份自動拉成那批交期涵蓋的範圍**（訂單 API 吃 month_to），表格、匯出一次包完不用逐月切，
  行事曆換成「這批動到的日期」卡片；清除時回到原本停的月份。匯入完成直接切到剛那批（第一眼就是剛匯的 PO）。
  行事曆可以按著滑過多選；另有「日期清單」切換（一列一天、Shift 連選）與「本週／下週／最近一批動到的天」快捷。
- **改單原因（2026-09-22，主管要算改單成本）**：人手改**出貨數量**或**交貨日**之前一定要選原因，選項寫死
  `common.CHANGE_REASONS`＝缺貨／沒車／酷澎要求／其他（選「其他」要寫一句說明）。不給人自由打字，因為「沒車」「無車」
  「車不夠」會變三種，統計不出來。存在 `mst_logs.reason`（舊紀錄留空）；「其他」的說明接在 `note` 後面。
  備註、恢復整合表數字／日期**不問**（那是把人改的撤掉，不是改單）；酷澎自己改的（source=import）也沒有原因，酷澎不會講。
  前端一個共用小視窗 `askReason()`，就地改數量、就地改期、批次改期、PO 視窗儲存四條路都走它；PO 視窗一次儲存整窗一個原因。
  後端沒帶原因回 400，一筆都不存。之後要做的統計頁（每月幾張 PO、幾張被改、改幾次、原因分佈）就靠這欄。
- **④ 改單統計（2026-09-22，`master/stats.py`）**：主管要「一段期間幾張 PO、涉及幾個 SKU、幾張被改過（佔比）、
  改了幾次、酷澎改的還是我們改的、我們改的原因、改最多次的 PO」，目的是把改單講成成本。算法全寫在 stats.py 檔頭，
  重點：**改單事件**＝同一張 PO、同一來源、同一時間（人改看秒、匯入看分鐘）的紀錄算一次，不然整張 PO 改期 20 個品項會算 20 次；
  **酷澎改的**看 `qty_file_ship`／`delivery_date_file` 兩個 import 紀錄＋品項消失，不看 `qty_ship`「隨整合表更新」那筆（同一件事會重複）；
  **我們改的**看 manual 的 `qty_ship`／`delivery_date`，「恢復為整合表…」不算。「每次改單約幾分鐘」是人填的，系統只乘出估計工時，
  留 0 就不顯示——這個數字系統不能自己決定。資料從 9 月中上線後才有；2026-09-22 前的人改沒有原因，列「未填」。
  匯出六個分頁（每月統計／改單原因／改了什麼／改最多次的 PO／明細／怎麼算的），檔名 `改單統計_2026-09～2026-10.xlsx`。
  第二版（同日）：畫面上每個藍色數字都能點，開「改單明細」視窗列出背後是哪幾次（時間／PO／誰／來源／改了什麼／原因），
  明細由 `/api/master/stats/events` 一次撈整段期間、前端過濾。「改了什麼」分改數量（再分下修／上修／有上有下）、改交期、
  品項被拿掉三類，一次改單可能同時改兩類所以加總會大於改單次數。**原則：主管要的東西統計頁越強、輸入端越不動**，
  原因維持四個、不往下拆，按人統計沒做（Jerry 說要先問主管）。
  **測試資料**（Jerry 明講不開測試站）：原因視窗多一個勾「這是測試，不算進統計」→ 原因記 `TEST_REASON`＝「測試」，
  不用選原因；統計／明細／Excel 預設排除，回 `test_events` 讓畫面寫「另有 N 次測試沒算」，統計頁勾「含測試」才算進去。
  匯入的測試靠「只看預覽不寫進系統」（視窗裡加了一句提醒）；不做「撤銷某一批匯入」，一批會同時新增與修改既有單，撤一半更亂。
  給同事的兩條規矩：正式站試改單就勾「這是測試」；試匯入只按預覽。
- **外部來源檔（2026-09-22，`master/sources.py`）**：總表其實是業務用四份外部檔 VLOOKUP 拼出來的工作台，
  每欄的意思與公式整理在 [`寶僑總表_欄位與公式對照.md`](寶僑總表_欄位與公式對照.md)（**改總表相關的東西先看它**）。
  Jerry 明講「公式與判讀才是重點」：值從源頭進、公式由系統照 Excel 原樣算、不追業務那一串連結。
  做法：同一個主檔匯入口看表頭認檔（supply 表／Coupang Master／庫存銷售表／總表），主檔多 GIV、NIV，
  新表 `mst_month_stats`（每商品每月 supply／demand／下單／實銷）與 `mst_source_uploads`（上次上傳）。
  剩餘庫存、庫存天數、到月底預估、PG 剩餘可供貨量都現算（`/api/master/month_stats`），公式列在 sources.py docstring。
  判讀規則：來源空白／#N/A／#REF 不覆蓋；來源沒有的商品不新建；月份沒寫年取離今天最近的一年；分頁不看名稱。
  發現：總表 BH～BJ 的庫存公式指歪了（第 23 欄現在是 8 月實銷），業務看的庫存多半是錯的；sell-thru 表路徑已失效，COGS 不接它。
  還沒接：酷澎銷售報表（實銷的真正來源，等檔）；Chloe 手填的 10/2、10/5、10/6 是什麼（等問）；庫存從 4 月起算 4 月前當 0（等業務確認）。
- **③ 總表看板（2026-09-23，`master/board.py`）**：總表搬進系統的第二步。目標是 Jerry 說的「Excel 表上的東西轉到介面上，
  看起來舒服、數字來源都對、業務要看的數字都在」。一次撈 `/api/master/board?line=&month=`，三個視圖同一份資料：
  **商品**（一列一商品，分組表頭：單價 COGS／GIV／NIV、N 月供需 Supply／demand／下單／剩餘可供貨、庫存 剩餘／天數／到月底、
  N 月金額 下單 GIV／COGS 含稅／永豐成本）、**品牌**（SUMIF 那一段：Supply GIV、下單 GIV、目標、達成、COGS 含稅、REBATE 目標、差距、庫存）、
  **每日出貨**（原本的寬表，各交貨日箱數＋月 TTL）。上面四張卡：N 月下單 vs Supply 已下 %、下單金額 GIV、剩餘庫存、需要注意。
  公式全部照總表算，寫在 board.py 檔頭（BE／BK／BN／BO／BP；庫存走 `sources.stock_by_barcode`）。
  列哪些商品：這個月「有下單」或「supply 表有給」或「有庫存資料」的；主檔有但三者皆無的不佔位（跟 Excel 一樣）。
  **目標與 REBATE 目標是人填的**（總表 CI／CS），存 `mst_brand_targets`（線別＋月份＋品牌唯一），品牌表那格點一下就能填、
  空字串清掉、每次都記歷程；不做匯入，因為總表那兩欄一季才改一次。警示：超打（下單 > Supply；Note 是「不可超打」的標紅）、
  庫存天數 < 14、算不出箱數、缺 GIV。Note 做成小標籤（新品／不可超打／可以超打／停產／停?／有放單直接給貨）。
  匯出總表按鈕還是走底稿填值（第三步要把 GIV／NIV／供需／庫存也填進去，見「還沒做」）。
- **對帳的算法留著、畫面拿掉**：品項數才能加（每筆只算在第一次出現那批的「新增」）；PO 數不能加，同一張 PO 兩次都動到會重複。
  這是回答 Jerry「為什麼全部少 10 張」時算給他看的，Chloe 覺得一堆數字看了不舒服，2026-09-16 整張對帳卡拆掉。
- **前端寫死 Tailwind**：static/tailwind.css 是預編譯的，新 class 沒編進去就沒效果、也不報錯 → 顏色類的東西用 inline style。`.hidden{display:none!important}` 是為了壓過 `.btn` 的 display。

## 四、做過又拆掉的（別再做回來）

| 拆掉的 | 為什麼 |
|---|---|
| 線別群組設定面板 | 只為了一條 CPG→紙潔 的規則，同事看不懂 |
| 上傳總表底稿按鈕 | 多一步；改成匯主檔時自動認出總表 |
| 匯入歷程獨立視窗（第一版） | 不直觀；融進匯出與「各次匯入的變動」下拉。第三版又收回一個**很簡單**的「匯入紀錄」小視窗：一次一列、點一列只看那次，沒有其他東西 |
| 「各次匯入的變動」下拉＋月份小按鈕＋對帳卡（第二版） | 字太多、匯 100 次下拉就 100 行；Chloe 看了不舒服。改成一行＋表格色條＋行事曆角標 |
| 匯出範圍下拉＋藍色標籤＋「已篩選」 | 三個東西講同一件事 |
| 「只看最近一次匯入的變動」第二顆按鈕、「共匯入 N 次」那句 | 廢話；留全部訂單＋下拉就好 |
| 選某次匯入自動跳月份 | 被當成 bug；改成月份標籤讓人自己點 |
| 配額(CS)／剩餘可供貨 兩欄 | 業務還沒確認，後端留著、畫面收起 |

## 五、資料模型（mst_ 前綴，跟訂單管理完全分開）

- `mst_products`：barcode UNIQUE；category/pgcode/cost_price/note（總表）、master_line/unit/shelf_days/active/date_format（酷澎主檔）、lines_seen（訂單學來＋主檔給的）、auto_created。
- `mst_orders`：UNIQUE(po_number, sku_id)；line 原始值；qty_ship/delivery_date/remarks 各自 `_overridden`；missing_in_file；version；first_batch_id/last_batch_id/last_batch_changes。
- `mst_import_batches`：預覽存 payload_json，確認後 committed=1。
- `mst_templates`：line UNIQUE，底稿整份 base64。
- `mst_month_stats`（每商品每月 supply／demand／下單／實銷／實銷天數，UNIQUE(barcode, month)）、`mst_brand_targets`（線別＋月份＋品牌的目標 GIV／REBATE 目標，人填）、`mst_source_uploads`（每次外部來源檔上傳一筆，畫面「上次上傳」）。
- `mst_quotas`、`mst_logs`（所有變動 append-only）、`mst_meta`（schema_version，目前 4；升級在 `db._migrate_master_columns`，用「缺欄就 ADD COLUMN」，跟版號無關）。
