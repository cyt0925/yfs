# YFS 訂單系統 設計筆記（portal.py，網址 /portal）

> 依據：Alice 2026-10-06 跟 Jerry 的對話（各通路後台＋最外層訂單系統入口），Jerry 同日在對話裡定的名字、配色、選單。
> 畫面雛形先做成可以點的網頁給 Jerry 看過三版才做進系統。

## 一、現在狀態

- **入口頁做好，在新網址 /portal 試用中。** 現在的首頁 `/` 還是酷澎訂單管理，沒有換掉（Jerry 同意先開新網址，同事看過說好再換）。
- 只讀不寫，不新增任何資料表；數字全部從既有的表現算，算法寫在 `portal.py` 檔頭。
- 酷澎有真資料；蝦皮特選「建置中」、PChome「規劃中」，**卡片不放假數字**。

## 二、大方向（為什麼這樣分）

- **一個系統分通路，不拆成好幾個系統。** 商品總檔、拆單、採購單、勇信核對、竹運拋檔各通路都要用，拆開每改一次規則要改好幾次；
  Ivan 要的跨通路彙整也要資料在同一個地方。Alice 說的「各通路分開比較乾淨」用畫面與資料分開做到。
- Alice 的重點原話：「所有的通路需要的功能大同小異，只是差在來源檔案格式不同」。之後每加一個通路，主要是寫「讀它的訂單檔」那一塊，
  其他用共用工具。現在瑪氏那套綁在酷澎訂單上，做蝦皮前要先改成哪個通路都能用。
- **EMMA 匯入檔只有買斷的訂單要做**（Jerry 2026-10-06）：目前買斷的是酷澎、PChome 的寶僑，其他通路都是寄倉。
  蝦皮特選是寄倉：流程跟酷澎瑪氏差不多，最後出竹運出貨檔、不出 EMMA。畫面上**不標買斷／寄倉**（Jerry：「買斷甚麼的不用特別說啦」）。
- Ivan 的目的：用數據呈現多餘的步驟花了多少時間和成本，拿去跟合作廠商談。改單統計是第一版；新通路從第一天就要記「誰、何時、做了什麼、為什麼改」。

## 三、畫面的決定

| 決定 | 原因 |
|---|---|
| 名字「YFS 訂單系統」 | Jerry 定的 |
| 配色酒紅：深紫 `#171028` 漸層到 `#96002a` | Jerry 給的漸層圖；寶僑藍（商品主檔、竹運）、黑紅（酷澎訂單管理）已經用掉。做過「茄紫」版比較，Jerry 選酒紅 |
| 版面照 YFS-AI 戰情室：左側選單＋上方標題列＋卡片 | 同事在兩邊切換時像同一套；戰情室那邊之後加一個選單連過來 |
| 首頁最上面是「今天要處理的事」，數字放第二 | 參考 Shopify 後台：給 OP 每天用的，待辦比業績重要；戰情室是給主管看的才是數字在上 |
| 左側選單酷澎底下放工具捷徑，照線別工具的分法（寶僑、瑪氏）排 | Jerry：「兩邊都有，捷徑的概念」；酷澎系統裡的線別工具照舊 |
| 驗收單簽名捷徑連 `/#sign`，進訂單管理直接打開簽名視窗 | Jerry 提醒漏了；`index.html` 讀到 `#sign` 就按簽名鈕 |
| 「看改單統計」連 `/master#stats` | `master.js` 讀到 `#stats` 就切到改單統計分頁 |
| 營運 SOP 檢索開在框裡（iframe），旁邊有「另開新分頁」 | SOP 是另一個獨立網站（GitHub Pages，網址見 `portal.SOP_URL`），不動它 |
| 線別名稱先用字，不用 logo | 做過寶僑、瑪氏 logo 白底小框版，Jerry 說「改成原本的」 |
| 通路顏色：酷澎藍、蝦皮橘、PChome 綠 | 驗證過的分類色前三格，色盲也分得開；顏色跟著通路走 |
