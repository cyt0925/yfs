# 酷澎訂單管理系統（Coupang OMS）

永豐商店 OP 團隊的本地端中繼站。把酷澎整合表無腦整份上傳，系統自動去重、
抓出酷澎偷偷改過的單、記錄誰在什麼時候改了什麼，最後一鍵匯出乾淨的 Excel。

## 怎麼跑起來

第一次要先裝套件（只需一次）：

```bash
pip install -r requirements.txt
```

之後每次啟動，**雙擊 `啟動系統.bat`** 就好，瀏覽器會自動打開。
（或者手動跑 `python app.py`，再開 <http://127.0.0.1:5000>。）

驗證系統邏輯是否正常（用真實整合表跑完整流程，46 項檢查）：

```bash
python test_flow.py
```

## 怎麼更新版本

**把整個 `coupang-oms` 資料夾解壓縮覆蓋掉就好，不用挑檔案。**

你的訂單資料和設定不在這個資料夾裡，而是在它隔壁：

```
酷澎訂單管理系統/
├── coupang-oms/        ← 程式碼。更新時整包覆蓋，隨便蓋
│   └── defaults/       ← 設定檔的出廠預設值（只在第一次啟動時複製過去）
└── 資料與設定/          ← 這個不要動
    ├── database.db         你匯入的所有訂單與修改歷程
    ├── config.json         操作人員名單、狀態選項
    ├── export_profiles.json 匯出欄位格式
    └── backups/            自動備份
```

第一次跑新版時，系統會自動把舊位置的 `database.db`、`config.json`、
`backups/` 搬到「資料與設定」資料夾，終端機會印出搬了什麼。之後就不會再動。

要備份的話，複製「**資料與設定**」這個資料夾就夠了，程式碼隨時可以重新下載。

## 核心防呆（這幾條是系統的命）

| 防呆 | 做法 |
|---|---|
| **一張 PO 有多個 SKU** | 唯一鍵是 `UNIQUE(po_number, sku_id)`。**不能**把 `po_number` 設成 UNIQUE——真實整合表裡一張 PO 最多有 29 個 SKU，那樣做會靜悄悄丟掉 80% 的資料、害倉庫少出貨。 |
| **改倉／改期不能變成新單** | `warehouse` 和 `delivery_date` 是整張 PO 共用、而且天天在改的欄位，所以它們是一般欄位、不進主鍵。放進主鍵會讓酷澎改倉時判定成「新單」而 INSERT 一份，產生數量翻倍的幽靈列。 |
| **重複 ≠ 變更** | 內容完全相同才靜默略過；只要數量／交期／倉別有差，就是酷澎偷改單，一律更新 + 寫歷程 + 標記待確認推到最上面。 |
| **消失 ≠ 取消** | 酷澎後台一次只給 20–60 筆，上傳的永遠可能是片段。資料庫有、檔案沒有的單，系統**完全不動**，只更新 `last_seen_at`。任何取消判定都必須由人決定。 |
| **匯入不覆蓋 OP 心血** | `qty_coupang` 只有匯入能改，`qty_ship` 只有人能改。OP 一旦手動調整過出貨數量（`qty_ship_overridden`），之後匯入永遠不再碰它。 |
| **全有全無** | 匯入分兩階段：先預覽報告（新增／更新／略過各幾筆、酷澎改了什麼），OP 按確認才實際寫入，中途任何一列出錯整批 rollback。寫入前自動備份 `database.db` 到 `backups/`。 |
| **三個人同時用不互蓋** | SQLite 開 WAL 模式解決資料庫層的鎖；業務層用 `version` 樂觀鎖，同事先存過就回 409 並提示重新載入，不會 last-write-wins。 |
| **歷程是證據** | `edit_logs` 是 append-only 的**欄位級**紀錄：哪張單／哪個欄位／改前／改後／誰／何時／來源（匯入 or 手動）。不存成一句中文字串，這樣才查得出「這個月被改過交期的單有哪些」。 |
| **匯出即拉單，但要 OP 自己決定** | 匯出時的「標記為已拉單」是可勾選的。試算匯出不會鎖單；正式匯出才標記 `is_pulled` 並鎖定編輯，取代以前每天複製一個 Excel 分頁記「拉到哪」的做法。 |
| **已拉單後又被改 = 最高警示** | 倉庫已經拿到舊資料了。這種單在匯入預覽階段就會先跳紅字警告，匯入後標成 `changed_after_pull`，在列表最頂端用紅底顯示。 |
| **解鎖要留原因** | 解除拉單鎖定必須填理由，理由會寫進歷程。 |
| **正規化只有一份實作** | `normalize.py` 是唯一入口。PO 單號強制當文字（否則 13 位數會被 Excel 轉成科學記號變成另一把鍵）、交期一律轉 ISO、倉別去空白轉大寫。匯入、查詢、比對全走同一條路徑。 |

## 拆單

酷澎拆單會產生**新的 PO 單號**，所以走的是一般的「新增」路徑，不需要任何猜測邏輯。
`parent_po` 欄位保留原訂單號做血緣追蹤，列表上會以 `↳原單 xxx` 顯示。

## 檔案

```
coupang-oms/
├── 啟動系統.bat            雙擊啟動
├── app.py                  Flask API：查詢、編輯、匯入兩階段、匯出
├── db.py                   SQLite schema、WAL 設定、資料夾搬遷、自動備份
├── importer.py             整合表解析與差異比對（系統的心臟）
├── normalize.py            欄位正規化，唯一實作
├── defaults/               設定檔出廠預設值（不是你在用的那份）
├── templates/index.html    單一頁面前端
├── test_flow.py            端到端驗證
└── samples/整合表範例.xlsx   測試用真實資料
```

## 匯出格式怎麼對齊 ERP

打開「**資料與設定**」資料夾裡的 `export_profiles.json`，找到 `erp` 這個 profile，
把 `columns` 改成公司 ERP 匯入規範要求的欄位名稱與順序即可，**不需要動任何程式碼**：

```json
{ "header": "ERP 欄位名稱", "field": "系統內部欄位", "format": "text|int|date|decimal" }
```

- `header` 想叫什麼就叫什麼，順序就是匯出欄位的順序
- `const` 可以輸出固定值（ERP 常見的公司別、單別等常數欄位）
- 改完存檔、重新整理網頁就生效

要新增其他格式（例如不同倉庫要不同版本），直接在 `profiles` 底下多加一個
區塊就會出現在匯出選單裡。

## 備份

每次匯入寫入前會自動把 `database.db` 複製到「資料與設定/backups/」，保留最近 30 份。
那只防「匯入出錯」，防不了整個資料夾被誤刪，所以建議定期把「**資料與設定**」
資料夾複製一份到公司雲端硬碟。
