# 聽錄音（Jerry 2026-10-16：「可以做一個在你這邊聽錄音的功能嗎」）

Claude 本身聽不到聲音，所以先用語音辨識模型把錄音轉成文字，再讀文字整理。全部在這個雲端環境裡跑，錄音不會傳到別的服務。

## 做法

```bash
bash .claude/skills/listen-recording/setup.sh          # 每個新的雲端環境第一次用：約 1 分半；裝過會直接結束
python .claude/skills/listen-recording/transcribe.py "<錄音檔>" "<scratchpad>/<檔名>_逐字稿.txt"
```

- Jerry 傳來的檔案在 `/root/.claude/uploads/<session>/` 底下，訊息裡會帶 `@"路徑"`。
- 輸出一行一段：`[分:秒] 內容`，已轉成繁體、台灣用語，數字轉成阿拉伯數字。
- 讀完逐字稿再整理：先講重點（決定了什麼、誰要做什麼、期限），再附逐字稿檔案路徑。辨識不確定的地方（專有名詞、數字、單號）
  標「聽不清楚／可能是」，不要當成確定的事實寫進結論。

## 紅線

- **錄音、逐字稿都是公司資料：只放 scratchpad，不能放進 repo、不能推上 GitHub。** 跟其他真實業務檔案一樣。
- 模型和套件放 `~/.cache/yfs-asr`（`ASR_CACHE` 可改），不進 repo（230 MB）。

## 能做、不能做（2026-10-16 實測）

- 模型：SenseVoice（中文普通話、粵語、英、日、韓）＋ silero 依停頓切段，套件 sherpa-onnx。
- 官方範例錄音辨識正確（「開飯時間早上9點至下午5點」）；11 分鐘的錄音 21 秒轉完（4 核）。
- **台語不支援**，會亂掉；這時要跟 Jerry 說，不要硬整理。
- **分不出是誰在講話**，逐字稿只有時間和內容。
- 吵雜環境、多人同時講、電話音質：**還沒用真的錄音驗證過**，第一次用真檔要跟 Jerry 說準確度看起來如何。
- 專有名詞（酷澎、瑪氏、勇信、蝦皮特選）、PO 單號、料號容易聽錯，整理時對照系統資料或標出來。

## 為什麼用這個模型

- 這個雲端環境的網路只開套件網站（PyPI、npm）和 GitHub；常見的 Whisper 模型放在 Hugging Face，被擋（403）。
  SenseVoice 在 k2-fsa/sherpa-onnx 的 GitHub 發布頁有，下載得到。
- 模型作者公布的中文測試成績比 Whisper 好（這是官方說法，我們沒有自己比過）；只用 CPU 也很快（上面的實測），不用顯示卡。
