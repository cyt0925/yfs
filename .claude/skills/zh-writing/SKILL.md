# 中文寫作規矩

這份是 Jerry 一路糾正累積下來的。每條後面附原話和日期，有疑問就照原話判斷。

## 一、跟 Jerry 講話（對話回覆）

1. **先講結論，一句只講一件事。** 先回答 Jerry 問的，再講細節。一段不要塞好幾件事。
2. **用口語，不用術語。** 程式的詞要換成 Jerry 聽得懂的說法：
   - 部署、deploy → 推上正式站、上線
   - commit、push → 存一版、推到開發分支
   - API、endpoint → 系統裡負責這件事的那一段
   - 欄位、field → 那一欄
3. **不用 ①②③ 這種代號，直接寫名字。** 「②到底是甚麼啦」（2026-10-01）。要寫「訂單明細分頁」，不寫「②」。
4. **Jerry 問問題時，先回答，不要直接動手。** 要做的事先複述一次理解，等 Jerry 說對再做。「之後請先理解我的問答在來開始做」（2026-09-23）。
5. **Jerry 說聽不懂，就換一種講法，舉實際例子。** 不要把同一句話再講一次。可以給 A、B 兩個選項讓 Jerry 選。
6. **有幾件並列的事，用條列或表格。** 一條最多兩句。
7. **結尾不要客套話。** 不寫「有任何問題歡迎再問」。要等 Jerry 決定的事，最後寫清楚要回什麼，例如「要上正式站就說 OK 推正式站」。

## 二、系統畫面上的字

1. **正式、簡潔，不口語。** 歷程視窗一開始的用字，Jerry 說「也太口語」（2026-10-05），後來改成「歷程紀錄」「操作人員」「查無紀錄」這種寫法。
2. **按鈕寫它實際做的事。** 「產出拆單表」改成「下載 EIP 採購單」，因為按下去下載的就是 EIP 採購單（2026-10-06）。
3. **同一件事只講一次。** 曾經三個地方講同一件事被糾正，提示、標籤、說明不要重複。
4. **名詞前後一致**，照這張表寫：

| 寫這個 | 不要寫 |
|---|---|
| YFS 訂單系統 | 入口、portal |
| 酷澎訂單管理系統 | 主系統、OMS |
| 今日事項 | 今天要處理的事 |
| 各通路系統 | 各通路 |
| EIP 採購單號 | EIP 單號、PO 號 |
| EMMA 匯入檔 | EMMA 檔案、匯入表 |
| 寶僑、瑪氏、紙潔 | P&G、Mars、CPG（畫面上） |
| PChome | PC Home、Pchome |

5. **畫面上不標買斷、寄倉。** 「買斷甚麼的不用特別說啦」（2026-10-06）。

## 三、用字與排版

1. **避開罕見字。** 「匯」「驟」曾被打成 Big5 裡沒有的字，同事看不懂。改到 repo 的檔案一律跑 `python coupang-oms/check_chinese.py`。對話沒有工具擋，送出前自己看一次，能換詞就換詞，例如用「做法」代替「步驟」。
2. **中文和英文、數字之間空一格。** 寫「EIP 採購單號」「3 份拆單」「2026-10-06」，不寫「EIP採購單號」。
3. **標點用全形**：，。、：「」（）。
4. **日期**：對話裡寫「10/6」，文件和畫面寫「2026-10-06」。數字三位一撇：8,041。

## 四、去掉翻譯腔

寫完照這張表檢查一次：

| 翻譯腔 | 改成 |
|---|---|
| 進行修改 | 改 |
| 針對這個問題 | 這個問題 |
| 透過按鈕來下載 | 按按鈕下載 |
| 被系統所記錄 | 系統會記下來 |
| 我將會處理 | 我會處理 |
| 做一個確認 | 確認 |
| 這是一個很重要的功能 | 這個功能很重要 |
| 基於上述原因 | 所以 |
| 在……的情況下 | ……的話 |
| 的的的連用（系統的訂單的狀態的顏色） | 拆開或省掉幾個「的」 |

## 五、送出前的檢查

1. 第一句就是答案嗎？
2. 有沒有 Jerry 看不懂的英文、縮寫或代號？
3. 每句只講一件事嗎？讀出來順不順？
4. 有沒有翻譯腔？
5. 畫面上的字是不是正式、名詞跟上面那張表一致？
6. 有沒有罕見字？
